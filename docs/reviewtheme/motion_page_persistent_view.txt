================================================================================
MOTION PAGE - PERSISTENT ZOOM AND PAN PER DEVICE
================================================================================
Date: 2025-10-29
Feature: Persist zoom and pan state for each device's graphics view
         When users navigate away and return, each device retains its view state

================================================================================
PROBLEM BEFORE
================================================================================

When working with multiple motion devices in the Motion Page:
1. User selects Device A and zooms/pans the graphics view
2. User switches to Device B
3. User switches back to Device A
4. The view resets to default zoom/pan (loses user's previous view state)
5. User must manually zoom/pan again to get back to desired view
6. This was tedious when frequently switching between devices

================================================================================
SOLUTION IMPLEMENTED
================================================================================

Implemented per-device view state persistence using QSettings:
1. Each device's zoom factor and pan position are saved separately
2. When switching away from a device, its current view state is saved
3. When switching to a device, its saved view state is restored automatically
4. View states persist across application restarts

================================================================================
IMPLEMENTATION DETAILS
================================================================================

Method: setDeviceName(const QString& deviceName)
- Sets the device name for the graphics view
- Required for QSettings key generation
- Must be called before save/restore operations

Method: saveViewState()
- Saves current zoom factor (m_zoomFactor)
- Saves view center point in scene coordinates
- Uses QSettings with key format: "MotionPage/{deviceName}/zoomFactor"
- Uses QSettings with key format: "MotionPage/{deviceName}/centerX"
- Uses QSettings with key format: "MotionPage/{deviceName}/centerY"
- Does nothing if device name is empty (safety check)

Method: restoreViewState()
- Checks if saved state exists for current device
- Returns early if no saved state found (uses default view)
- Resets transform to identity
- Applies saved zoom factor using scale()
- Centers view on saved center point using centerOn()
- Updates viewport to reflect changes
- Does nothing if device name is empty (safety check)

Integration in MotionPage::onDeviceChanged():
1. Before switching: Save current device's view state (if not empty)
2. After switching: Set new device name and restore its view state
3. Restore happens after refreshPositionDisplay() to avoid conflicts

================================================================================
QSettings STORAGE
================================================================================

Settings are stored in QSettings (platform-specific location):
- Windows: Registry or .ini file
- Linux: ~/.config/organization/application.conf
- macOS: ~/Library/Preferences/com.organization.application.plist

Keys stored per device:
- MotionPage/{deviceName}/zoomFactor (double)
- MotionPage/{deviceName}/centerX (double)
- MotionPage/{deviceName}/centerY (double)

Example:
- MotionPage/Gantry/zoomFactor = 1.5
- MotionPage/Gantry/centerX = 123.45
- MotionPage/Gantry/centerY = -67.89

CODE LOGIC
================================================================================

MotionGraphicsView.cpp - saveViewState():
```cpp
void MotionGraphicsView::saveViewState()
{
  if (m_deviceName.isEmpty()) {
    return;  // Can't save without a device name
  }

  QSettings settings;
  QString prefix = QString("MotionPage/%1/").arg(m_deviceName);

  // Save zoom factor
  settings.setValue(prefix + "zoomFactor", m_zoomFactor);

  // Save view center point (in scene coordinates)
  QPointF centerPoint = mapToScene(viewport()->rect().center());
  settings.setValue(prefix + "centerX", centerPoint.x());
  settings.setValue(prefix + "centerY", centerPoint.y());
}
```

MotionGraphicsView.cpp - restoreViewState():
```cpp
void MotionGraphicsView::restoreViewState()
{
  if (m_deviceName.isEmpty()) {
    return;  // Can't restore without a device name
  }

  QSettings settings;
  QString prefix = QString("MotionPage/%1/").arg(m_deviceName);

  // Check if saved state exists
  if (!settings.contains(prefix + "zoomFactor")) {
    return;  // No saved state for this device
  }

  // Restore zoom factor
  double savedZoomFactor = settings.value(prefix + "zoomFactor", 1.0).toDouble();
  double savedCenterX = settings.value(prefix + "centerX", 0.0).toDouble();
  double savedCenterY = settings.value(prefix + "centerY", 0.0).toDouble();

  // Reset transform first
  resetTransform();
  m_zoomFactor = 1.0;

  // Apply saved zoom
  double scaleFactor = savedZoomFactor / m_zoomFactor;
  scale(scaleFactor, scaleFactor);
  m_zoomFactor = savedZoomFactor;

  // Center on saved position
  centerOn(QPointF(savedCenterX, savedCenterY));

  viewport()->update();
}
```

MotionPage.cpp - onDeviceChanged():
```cpp
void MotionPage::onDeviceChanged(const QString& deviceName)
{
  // ✅ NEW: Save current device's view state before switching
  if (!m_currentDevice.isEmpty() && m_graphicsView) {
    m_graphicsView->saveViewState();
  }

  m_currentDevice = deviceName;

  // ... device switching logic ...

  refreshPositionDisplay();
  m_controlPanel->clearSelectedPosition();
  m_selectedPositionName.clear();

  // ✅ NEW: Set device name and restore its saved view state
  if (m_graphicsView) {
    m_graphicsView->setDeviceName(m_currentDevice);
    m_graphicsView->restoreViewState();
  }

  // If no positions loaded, auto-fit will center on device marker
}
```

================================================================================
EDGE CASES HANDLED
================================================================================

✅ First time selecting a device (no saved state)
   → restoreViewState() returns early, uses default view

✅ Empty device name
   → Both save/restore return early, no operation performed

✅ Application restart
   → QSettings persists across restarts, view states restored

✅ Multiple devices with different zoom/pan
   → Each device stores its own state independently

✅ Switching rapidly between devices
   → Each switch saves current and restores target correctly

✅ Graphics view pointer is null
   → Null checks in MotionPage prevent crashes

================================================================================
CLEANUP (IF NEEDED)
================================================================================

To clear all saved view states:
1. Close application
2. Delete QSettings keys:
   - Windows: HKEY_CURRENT_USER\Software\{Organization}\{Application}
   - Linux: rm ~/.config/{organization}/{application}.conf
   - macOS: defaults delete com.{organization}.{application}
3. Restart application → All devices use default view

To programmatically clear a device's view state:
```cpp
QSettings settings;
settings.remove(QString("MotionPage/%1").arg(deviceName));
```
