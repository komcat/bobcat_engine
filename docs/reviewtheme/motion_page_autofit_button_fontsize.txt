================================================================================
PROBLEM 1: AUTO-FIT ON DEVICE SWITCH CONFLICTS WITH PERSISTENCE
================================================================================

After implementing persistent zoom/pan per device, the auto-fit behavior when
switching devices was problematic:

1. User zooms/pans to specific area on Device A
2. User switches to Device B
3. System saves Device A's view state (correct)
4. System loads Device B's positions and calls autoFitView() (PROBLEM!)
5. This overwrites any previously saved view state for Device B
6. User switches back to Device A
7. Saved view is restored correctly for Device A
8. But Device B's manually adjusted view is lost due to auto-fit

Result: Persistent zoom/pan was partially broken by auto-fit on switch.

================================================================================
SOLUTION 1: MANUAL AUTO-FIT BUTTON
================================================================================

Changes:
1. Removed automatic autoFitView() call when loading device positions
2. Added new "⊡ Auto Fit View" button in MotionControlPanel
3. User can now manually trigger auto-fit when desired
4. Persistent zoom/pan works correctly without interference

Benefits:
✅ Persistent view state now works perfectly
✅ User has explicit control over when to auto-fit
✅ Manual auto-fit is still available when needed
✅ Natural workflow: set your view once, it stays that way

================================================================================

6. Switch back to Device A
7. View restores to 5x zoom ✅
8. Switch to Device B again
