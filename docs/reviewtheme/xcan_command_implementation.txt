================================================================================
XCAN COMMAND IMPLEMENTATION - HEXAPOD ADAPTIVE SCANNING
================================================================================
Date: 2025-10-29
Feature: New sequence command for automated hexapod scanning in recipes/programs

================================================================================
OVERVIEW
================================================================================

Created a new XCAN command in the motion category that brings the hexapod
scanning functionality (previously UI-only) into the sequence/recipe system.

This allows recipes and programs to perform automated adaptive scanning to
find optimal alignment positions without manual intervention.

================================================================================
COMMAND SPECIFICATION
================================================================================

**Category:** Motion
**Command Name:** XCAN
**Device Restriction:** PI hexapods only (hex-* pattern)

**Required Parameters:**
- mode: "coarse" or "fine"
- channel: Data channel name to optimize

**Optional Parameters:**
- settling_time_ms: Motion settling time (default: 300ms)

================================================================================
FEATURES IMPLEMENTED
================================================================================

✅ Device Validation
   - Only accepts devices matching "hex-*" pattern
   - Rejects non-hexapod devices with clear error message

✅ Dual Mode Support
   - Coarse mode: 10→5→2→1 µm step sizes (matches UI Coarse button)
   - Fine mode: 2→1→0.5 µm step sizes (matches UI Fine button)

✅ ZYX Axis Scanning
   - Scans in Z→Y→X order
   - Each axis optimized sequentially
   - Positions device at global maximum

✅ Synchronous Execution
   - Command blocks until scan completes
   - Integrates with sequence stop flag
   - Uses callbacks and condition variables for coordination

✅ Stop Flag Monitoring
   - Checks context->stopRequested every 100ms
   - Halts scan gracefully when stop requested
   - Returns to best position found before stopping

✅ Comprehensive Logging
   - Logs start parameters
   - Logs progress during scan
   - Logs completion with peak value
   - Logs errors with details

✅ Error Handling
   - Validates all parameters
   - Checks DataStore availability
   - Reports scan failures
   - Handles "no peak found" cases

================================================================================
SCAN PARAMETERS (FIXED)
================================================================================

Motion Settings:
- Velocity: 50% of max
- Settling time: 300ms (default, configurable)
- Axes scanned: Z, Y, X (in that order)

Coarse Mode Step Sizes:
- 10 µm (0.010 mm)
- 5 µm (0.005 mm)
- 2 µm (0.002 mm)
- 1 µm (0.001 mm)

Fine Mode Step Sizes:
- 2 µm (0.002 mm)
- 1 µm (0.001 mm)
- 0.5 µm (0.0005 mm)

Termination Criteria:
- Consecutive decreases: 3
- Significant decrease threshold: 5%
- Max total distance: 0.2mm (200µm) per direction
- Improvement threshold: 1%

Measurement:
- Averaging count: 3 samples
- Measurement timeout: 5 seconds
- Valid value range: -1000.0 to 1000.0

Safety:
- Max step size: 0.5mm (500µm)
- Scan timeout: 10 minutes

================================================================================
TECHNICAL IMPLEMENTATION
================================================================================

Device Validation:
```cpp
std::regex hexPattern("^hex-.*");
if (!std::regex_match(deviceName, hexPattern)) {
  errorMessage = "XCAN: Device must be a PI hexapod (hex-*), got: " + deviceName;
  return false;
}
```

Mode Parsing:
```cpp
bool isCoarse;
if (mode == "coarse") {
  isCoarse = true;
} else if (mode == "fine") {
  isCoarse = false;
} else {
  errorMessage = "XCAN: Invalid mode '" + mode + "' (must be 'coarse' or 'fine')";
  return false;
}
```

Synchronous Execution Pattern:
```cpp
std::atomic<bool> scanComplete(false);
std::atomic<bool> scanSuccess(false);
std::mutex completionMutex;
std::condition_variable completionCV;

// Setup callbacks to signal completion
scanController.SetCompletionCallback([&](const ScanResults& results) {
  std::lock_guard<std::mutex> lock(completionMutex);
  scanComplete = true;
  scanSuccess = results.globalPeak.valid;
  completionCV.notify_one();
});

// Start scan
scanController.StartScan(scanParams);

// Wait with stop flag monitoring
while (!scanComplete) {
  if (context && context->stopRequested.load()) {
    scanController.HaltScan();
    return false;
  }
  std::unique_lock<std::mutex> lock(completionMutex);
  completionCV.wait_for(lock, std::chrono::milliseconds(100));
}
```

COMPARISON: XCAN vs UI SCANNING
================================================================================

| Feature | XCAN Command | UI Scanning (ScanControlWidget) |
|---------|--------------|----------------------------------|
| Trigger | Automatic in sequence | Manual button press |
| Device | From sequence | User selects L/R buttons |
| Mode | Parameter | Separate buttons |
| Channel | Parameter | Dropdown |
| Blocking | Yes (waits) | No (async with signals) |
| Stop | Sequence stop flag | UI stop button |
| Logging | SequenceContext | LogManager + UI log widget |
| Use Case | Automation | Manual operation |

Both use the same underlying AdaptiveScanController!
