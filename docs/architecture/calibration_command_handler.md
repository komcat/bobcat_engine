# CalibrationCommandHandler Layout

`include/sequence/CalibrationCommandHandler.{h,cpp}` + `include/sequence/calibration/`

Same pattern as Motion / Vision / CustomServer — orchestrator stays thin (~106 lines), per-family helpers under `calibration/`. The orchestrator owns two cross-family utilities (`GetCurrentDateTime`, `EnsureCalibrationDirectoryExists`) that helpers reach via `deps.parent->...`; all 19 calibration command branches live in the per-family helpers.

| File | Owns |
|------|------|
| `CalibrationCommandHandler.{h,cpp}` | Dispatch ladder (6 `TryExecute` calls + "Unknown calibration method" fallthrough), `m_context`, plus the two shared utilities `GetCurrentDateTime(bool dateOnly)` and `EnsureCalibrationDirectoryExists(errorMessage)`. ~106 lines, no per-command logic. |
| `calibration/CalibCommandDeps.h` | `struct CalibCommandDeps` — `ApplicationContext* app` (covers all manager pointers via `app->motionManager` / `app->productPositionManager` / `app->logManager`) + `CalibrationCommandHandler* parent` (callback handle for the two shared utilities). Built once in `ExecuteCommand` and reused. |
| `calibration/CalibYawMath.h` | Inline `calib_yaw::CalculateYawAngle(c1x, c1y, c2x, c2y, logger)` — `atan2(deltaX, deltaY)` measured from +Y, used by Families E and F. Shared via header rather than duplicated; the convention is baked into how downstream branches apply correction signs (see Family E's `ApplyYawCorrection`), so the function must stay shared. |
| `calibration/CalibNavigationCommands.{h,cpp}` | Family A: `LoadExistingCalibration`, `CapturePosition`, `SaveNavigationData`. Owns `config/SYSTEM/navigation_<uid>.json` (camera-position-only record). |
| `calibration/CalibNeedleZCommands.{h,cpp}` | Family B: `SaveNeedleZCalibration`, `LoadNeedleZCalibration`. Owns `config/SYSTEM/needle_z_calibration.json`. Save path computes a delta-vs-previous-calibration message and surfaces it back through the `deltaMessage` out-param. |
| `calibration/CalibCameraOffsetCommands.{h,cpp}` | Family C: `LoadCameraToNeedleOffset`, `SaveCameraToNeedleOffset`. Owns the `config/SYSTEM/needlexyoffset[.local].json` local-first override pattern (read prefers `.local`, write always targets `.local` so the factory default is preserved). Reports `loadedFromPath` so the dispatch branch can label the source as FACTORY vs LOCAL in logs. |
| `calibration/CalibDispenseZCommands.{h,cpp}` | Family D: `LoadDispenseZHeight`, `SaveDispenseZHeight`. Owns `config/SYSTEM/dispense_z_<uid>.json`. |
| `calibration/CalibYawCorrectionCommands.{h,cpp}` | Family E: `LoadYawCorrectionData`, `CalculateAndSaveYawCorrection`, `NavigateToSavedCorner`, `ApplyYawCorrection`, `ShowYawCorrectionResult`, `SaveYawCorrectionToPosition`. Owns `config/<product>/instances_data/yaw_correction_<uid>.json`. Largest helper (~487 LOC). `SaveYawCorrectionToPosition` is here (not its own family) because it consumes the `u_correction` context value the yaw flow produces — it writes the result back through `ProductPositionManager::AddPosition` + `SaveProduct` and refreshes the motion-manager cache. |
| `calibration/CalibYawToTemplateCommands.{h,cpp}` | Family F: `LoadYawToTemplateData`, `CalculateYawToTemplateCorrection`, `ApplyYawToTemplateCorrection`, `ShowYawToTemplateResult`. Owns `config/<product>/instances_data/yaw_to_template_<uid>.json`. Sibling of E but kept separate — the workflow differs (template-relative correction = `template_yaw - target_yaw` from two independent corner pairs, vs. E's "compare current corner pair against previous calibration"). Reuses `calib_yaw::CalculateYawAngle` from `CalibYawMath.h`. |

Helper contract is identical to Motion/Vision/CustomServer: `static std::optional<bool> TryExecute(deviceName, methodName, params, errorMessage, context, deps)` returning `std::nullopt` ("not mine"), `true` (success), or `false` (handled failure with `errorMessage`). The orchestrator stays flat — six `if (auto r = HelperX::TryExecute(...)) return *r;` calls, then "Unknown calibration method" fallthrough.

`m_logger` is reached as `deps.app->logManager` (the ApplicationContext field, same instance the dispatcher injects into `ICommandHandler::m_logger`).

**Cross-family utility access:** when a helper needs the SYSTEM-folder directory check or the timestamp formatter, it calls `deps.parent->EnsureCalibrationDirectoryExists(errorMessage)` / `deps.parent->GetCurrentDateTime(dateOnly)`. Both are `public:` on the orchestrator. Family E and F do *not* use `EnsureCalibrationDirectoryExists` — their files live under `config/<product>/instances_data/`, not `config/SYSTEM/`, and each helper creates its own product subdirectory inline.

**Adding a new calibration command:** put it inside the helper that owns the matching data file. If it touches navigation (camera position record), that's `CalibNavigationCommands`. Needle Z global → `CalibNeedleZCommands`. Camera-to-needle offset → `CalibCameraOffsetCommands`. Dispense Z per-DUT → `CalibDispenseZCommands`. Corner-pair yaw against a previous calibration → `CalibYawCorrectionCommands`. Template-relative yaw → `CalibYawToTemplateCommands`. If it starts a brand-new family, mirror the playbook: new helper under `calibration/`, register `.cpp` in CMakeLists `SOURCES` and `.h` in the headers list, include in the orchestrator, add one `TryExecute` call to the dispatch ladder.
